# Modem relay (V.150.1)

Usually, a modem call through the internet sends the digitized sound of
the modem on the full path. The modem at the far end must hear the tones
of D-Modem through all gateways and codecs on the path. **Modem relay**
(ITU-T V.150.1) uses a different method. A gateway near the far modem
answers the tones of that modem. It sends only the data, as plain bytes,
through the internet. The gateway sends lost packets again. Thus, the data
arrives correctly also on a bad network, and the codec on the path has no
effect.

D-Modem can be the other end of this type of call. dmodemd on SIP uses
V.150.1 directly. It is its own gateway. Thus, the far gateway sends the
data directly to it, and D-Modem does not use modem sound. Secure
telephones (STE) and the modem gateways of some carriers use this.

For the full technical description, refer to
[the technical details](v150-details.md).

## Turning it on

Modem relay is disabled by default. To enable it:

    SIP_V150=yes dmodemd ...

Then dmodemd offers modem relay on the data calls that it makes, together
with the usual audio. It accepts modem relay on calls that offer it. If
the far end does not accept it, the call continues as a usual audio call.
Thus, there is no problem when the far end does not have V.150.1. dmodemd
never relays fax calls and voice calls.

## What the user sees

The AT commands do not change. `ATD` and `ATA` operate as usual.

- **Calls out:** The modem dials and waits for the answer tone as usual.
  The far gateway sends that tone as an event, and dmodemd plays it to the
  modem. Then the modem changes to the relay, and the gateways agree on a
  modulation. `CONNECT` gives the speed at which the far modem connected
  (for example `CONNECT 33600`).
- **Answers:** The modem answers, and dmodemd sends the answer tone as an
  event. The gateway that calls changes the call to the relay. Then you
  get `CONNECT` as above.
- **Hang-up:** `ATH` stops the relay and the call. A hang-up at the far
  end does the same. If the far gateway stops the relay, you get
  `NO CARRIER`.

The speed in `CONNECT` is the speed between the far modem and its own
gateway. The data between the gateways goes as fast as the network
lets it. dmodemd keeps the data at that speed for the modem.

## Limits

- The modem relay offers the modulations V.34, V.32bis, V.22bis and V.21.
  The link between the far modem and its gateway sets the speed.
- dmodemd sends data as plain bytes and does not compress it. Some far
  gateways do not decompress the V.42bis or V.44 data of their modem, and
  let dmodemd do it (gateways that are not "double trans-compression",
  `mg=2`). dmodemd clears down such a gateway if its modem compresses.
- The far gateway must use the procedure of the audio answer tone
  (`CDSCselect=1`, the default V.150.1 behaviour). Some gateways change
  the call to voice band data. Such a gateway stops the relay, and the
  modem gives `NO CARRIER`.
- We tested it with the gateway of the test suite. We did not test it
  with a commercial gateway.
