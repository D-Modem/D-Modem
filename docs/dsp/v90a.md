# V.90 and V.92: the analogue modem

This page is about D-Modem as the **analogue** end of a 56k call. This end is
the modem of the customer on an ordinary phone line. It calls the V.90 or V.92
server of an internet provider (refer to
[the two ends of a 56k call](README.md#the-two-ends-of-a-56k-call)).
D-Modem operates as this end when it operates real modem hardware with
`dmodemd -a` or `dmodemd --usb` (refer to [Softmodem hardware](../hardware.md)).

For the plan, each phase of the start-up, the receiver and the tests,
refer to [the technical details](v90a-details.md).

## Status

All of these parts are complete and enabled by default:

| Part | What it gives |
|---|---|
| V.90 | up to 56000 bit/s down, 33600 up |
| Retrains and speed changes during a call | the call adapts when the line changes |
| V.92 with modem-on-hold | the call can wait while you accept a call-waiting call |
| V.92 PCM upstream | up to 48000 bit/s up instead of 33600 |
| V.92 quick connect | a faster start-up, about one second sooner on each call |
| Speed changes for PCM upstream | the two directions can adapt |

We tested it against the digital modem of D-Modem on a simulated
network, because that is the only digital modem that is available for tests.
We did not try it on a real phone line against the server of a real
provider yet.

## Settings

- Keep the line at **9600 Hz** (the default, `-r 9600`). At 8000 Hz, the
  clock of the modem and the clock of the network drift apart. Then the
  modem loses the 56k signal after some seconds, again and again. Thus,
  V.90 is disabled at 8000 Hz, if you do not set `DSP_V90A=1`.
- `DSP_V90A=0` disables V.90 as the analogue modem (the modem uses V.34 instead).
- `DSP_V92A_UP=0` disables only the faster V.92 upload.
