# V.44: data compression

This page describes ITU-T Recommendation V.44 (11/2000), "Data
compression procedures". It is our own description. It is not a copy of
the Recommendation. For the normative text, refer to the Recommendation
(`docs/specs/fetch.sh V.44`). For the codes, the parameters and the
procedures, refer to [the technical details](v44-details.md).

## Summary

V.44 makes the data from the computer smaller before the modem sends
it. It compresses better than [V.42 bis](v42bis.md), and it is faster.

- The compression operates on the error-corrected link of V.42. A lost
  or damaged frame breaks the compression, so error correction is
  necessary.
- The encoder keeps a history of the characters that it sent, and a
  dictionary of the strings in that history. For each string that it
  finds again, it sends a codeword. After a codeword, it can send a
  length: the string continues for that number of characters, as it did
  in the history.
- The decoder makes the same history and the same dictionary from the
  codes that it receives. Thus, the dictionary is never sent.
- The two directions can have different parameters: the number of
  codewords, the maximum length of a string, and the size of the
  history.
- When the data does not compress, the encoder changes to transparent
  mode and sends the characters as they are.
- The two modems agree on the use and the parameters of V.44 in the XID
  exchange of V.42.

## Where V.44 is used

V.92 modems have V.44. Many V.90 modems got it in a firmware update.
Annex B adds a packet method for packet networks.

## Related standards

- V.42: the error correction (LAPM) under V.44, and the XID exchange
  that negotiates it.
- [V.42 bis](v42bis.md): the older compression. A modem can offer the
  two, and the other modem selects one.
- [V.92](v92.md): the modem standard that uses V.44.
