# V.152: voice band data over IP

This page describes ITU-T Recommendation V.152 (09/2010), "Procedures
for supporting voice-band data over IP networks". It is our own
description. It is not a copy of the Recommendation. For the normative
text, refer to the Recommendation (`docs/specs/fetch.sh V.152`). For
the attributes and the procedures, refer to
[the technical details](v152-details.md).

## Summary

V.152 tells how a VoIP network carries the signals of modems, fax
machines and text telephones as audio. This is voice band data (VBD).

- A VBD channel uses a codec that keeps the modulated signal, usually
  G.711 (A-law or µ-law). Each end must support both laws.
- In VBD mode, the latency is constant. There is no voice activity
  detection, no comfort noise and no DC removal.
- SDP marks a VBD payload type with `a=gpmd:<pt> vbd=yes`.
- `a=maxmptime` gives the longest packet time of each format. A sender
  must not send longer packets.
- The assured VBD mode adds redundancy (RFC 2198) or FEC (RFC 5109), and
  RFC 4733 events for the tones of the modems.
- A gateway changes from audio to VBD when it detects a modem or fax
  tone, such as the 2100 Hz answer tone.

## Where V.152 is used

SIP and H.248 gateways and IP telephones use V.152 for modem and fax
calls when they have no T.38 or V.150.1.

## Related standards

- [V.150.1](v150-1.md): modem relay, which can use VBD in its start.
- [G.711](g711.md): the usual VBD codec.
- RFC 2198: redundancy. RFC 4733: telephone events.

## V.152 in D-Modem

`dmodemd` on SIP is a VBD endpoint. The code is in
`frontend/dmodemd/sip.cpp`. `SIP_V152=no` removes the V.152 attributes.
