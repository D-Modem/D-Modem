# V.80: synchronous access mode

This page describes ITU-T Recommendation V.80 (08/96), "In-band DCE
control and synchronous data modes for asynchronous DTE". It is our own
description. It is not a copy of the Recommendation. For the normative
text, refer to the Recommendation (`docs/specs/fetch.sh V.80`). For the
codes, the parameters and the procedures, refer to [the technical
details](v80-details.md).

## Summary

V.80 lets a computer with a usual serial port send a synchronous bit
stream through a modem. The computer does its own framing, for example
the frames of a videophone. The modem does not do error correction or
compression.

- The computer and the modem exchange octets with start and stop bits.
  On the line, the modem sends the bits with no start and stop bits.
- Commands and indications go in the same stream as the data, after an
  escape octet, EM (19h). These are "in-band" commands.
- If the data has an EM, DC1 or DC3 octet, a two-octet code replaces it
  ("shielding").
- **Transparent sub-mode:** the modem sends each octet as it is. When the
  computer has no data, the modem sends a SYN octet.
- **Framed sub-mode:** the modem sends HDLC frames. It adds the flags,
  the zero insertion and, if necessary, the FCS. It tells the computer
  if each received frame is good or bad.
- With in-band commands, the computer can ask for a retrain or a rate
  renegotiation. It can also change the highest rates, or end the
  carrier. The modem tells the computer about each of these events.

## Where V.80 is used

H.324 videophones use V.80 to send H.223 frames over a modem. Software
that does V.42 or other protocols in the computer can also use it.

## Related standards

- V.250: the AT commands. `AT+ES` starts the synchronous access mode.
- V.42: the FCS-16 and FCS-32 of the framed sub-mode.
- H.324 and H.223: the videophone and its multiplexer.
- V.8: the call function that selects H.324.
