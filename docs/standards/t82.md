# T.82: JBIG coding of bi-level images

This page describes ITU-T Recommendation T.82 (03/93), "Progressive
bi-level image compression" (JBIG). It is our own description. It is
not a copy of the Recommendation. For the normative text, refer to the
Recommendation (`docs/specs/fetch.sh T.82`). For the data format and
the coder, refer to [the technical details](t82-details.md).

## Summary

T.82 codes a bi-level image (each pixel is black or white) with no
loss of data. It codes better than MH, MR and MMR, mostly on halftone
images.

- An adaptive arithmetic coder (the QM coder) codes each pixel. A
  context of 10 pixels near the pixel selects a probability state.
- The template gives the context. It has three lines or two lines. One
  pixel of the template (the AT pixel) can move to the left.
- Typical prediction (TP) codes a line that is the same as the line
  above it with one bit.
- The data is a BIE: a header (BIH), then the coded data of each
  stripe. A stripe is a group of L0 lines. Marker segments can change
  the AT pixel, give a new page length, carry a comment, or stop the
  image.
- T.82 also has progressive coding: layers of lower resolution first.
  Fax does not use it (T.85).

## Where T.82 is used

Fax uses T.82 through [T.85](t85.md) (bi-level pages), [T.43](t43.md)
(colour pages as bit-planes) and [T.44](t44.md) (the mask of a mixed
raster page). JBIG2 (T.88) is a different standard.

## Related standards

- [T.85](t85.md): the fax profile of T.82.
- [T.4](t4.md) and [T.6](t6.md): the other bi-level codings.
- [T.30](t30.md): negotiates JBIG.

## T.82 in D-Modem

`dsp/jbig.cpp` codes and decodes T.82 sequential images with one or
more bit-planes. It does not code progressive images.
