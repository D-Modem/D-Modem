# T.38: fax over IP

This page describes ITU-T Recommendation T.38 (11/2015), "Procedures
for real-time Group 3 facsimile communication over IP networks". It is
our own description. It is not a copy of the Recommendation. For the
normative text, refer to the Recommendation (`docs/specs/fetch.sh
T.38`). For the packets, the transport and the SDP parameters, refer
to [the technical details](t38-details.md).

## Summary

T.38 sends a fax call over an IP network as packets, not as audio. A
gateway demodulates the fax signals and sends their data. The far
gateway modulates the data again for its fax machine.

- The packets are IFP packets. An indicator packet tells which signal
  starts (CNG, CED, V.21 flags, a fast modulation and its training). A
  data packet carries the data of a signal: HDLC frames, or T.4 page
  data.
- The packets are coded in ASN.1 PER (Annex A). Version 0 (1998) and
  versions 1 to 3 (2002 and later) use slightly different codings.
- UDPTL carries the packets on UDP. Each UDPTL packet has a sequence
  number. It can also carry the packets before it again (redundancy),
  or FEC data.
- On UDP, the TCF goes from fax machine to fax machine (data rate
  management method 2).
- SIP and SDP negotiate T.38 (Annex D), with parameters such as
  `T38FaxVersion` and `T38FaxUdpEC`.

## Where T.38 is used

VoIP networks use T.38 for fax, because fax audio does not pass well
through codecs, jitter and packet loss. Asterisk, FreeSWITCH, and most
SIP trunks and ATAs support T.38.

## T.38 in D-Modem

`dsp/t38.cpp` codes the IFP packets and UDPTL. The T.30 machine, Class 1
and Class 2 operate as T.38 terminals: they send and receive the
packets directly, with no audio. `dmodemd` and `dmodem-ari` negotiate
T.38 with SIP re-INVITEs.
