# V.8: the start of a data call

This page describes ITU-T Recommendation V.8 (11/2000), "Procedures for
starting sessions of data transmission over the public switched telephone
network". It is our own description. It is not a copy of the
Recommendation. For the normative text, refer to the Recommendation
(`docs/specs/fetch.sh V.8`). For the signals, the timing and the codes,
refer to [the technical details](v8-details.md).

## Summary

V.8 is a short exchange at the start of a call, before the modems train.
In this exchange, the call modem sends a list of the modulations that it
can use. The answer modem replies with the modulations that the two
modems share. Then the two modems start the best shared modulation.

V.8 has these functions:

- It selects the modulation automatically. Before V.8, a modem had to try
  each modulation in a fixed sequence.
- It tells the telephone network which modulation the call will use.
  Some network equipment compresses voice circuits, and must know this to
  let the data through.
- It tells the type of call (data, fax, text telephone and other types).
  Thus, a line with more than one device can send the call to the correct
  device.
- It controls the echo cancellers of the network, as V.25 does.

V.34, V.90, V.91 and V.92 must start with V.8. Older modulations (V.32bis,
V.22bis, V.21 and others) can start with V.8 or without it.

## How a V.8 call starts

1. The call modem dials.
2. The answer modem answers and sends ANSam, a 2100 Hz answer tone with
   a 15 Hz amplitude modulation.
3. The call modem identifies ANSam. Then it sends its call menu (CM) again
   and again. CM tells the type of call and the modulations of the call
   modem.
4. The answer modem replies with the joint menu (JM). JM tells the
   modulations that the two modems share.
5. The call modem sends CJ to stop the exchange.
6. The two modems start the best shared modulation. V.34 has the highest
   priority and V.21 has the lowest. If the two modems can do PCM, the call
   continues as V.90, V.91 or V.92.

All of the menus go at 300 bit/s on the two channels of V.21. Thus, the
exchange takes about one second.

If the answer modem sends a plain answer tone (ANS of V.25), it cannot do
V.8. Then the call modem uses an older start-up.

## Related standards

- [V.21](https://www.itu.int/rec/T-REC-V.21): the modulation of CI, CM and JM.
- [V.25](https://www.itu.int/rec/T-REC-V.25): the answer tone ANS and the
  procedure to disable echo cancellers.
- [V.8 bis](https://www.itu.int/rec/T-REC-V.8bis): an optional exchange
  before V.8.
- [V.34](https://www.itu.int/rec/T-REC-V.34),
  [V.90](https://www.itu.int/rec/T-REC-V.90),
  [V.91](https://www.itu.int/rec/T-REC-V.91),
  [V.92](https://www.itu.int/rec/T-REC-V.92): the modulations that must
  start with V.8. V.92 also has a shorter version of V.8 (quick connect).
- [V.251](https://www.itu.int/rec/T-REC-V.251): AT commands that control
  V.8 (`+A8E` and others).

## V.8 in D-Modem

`dsp/dp_v34.cpp` does V.8 for V.34, V.90, V.91 and V.92 calls, as the
call modem and as the answer modem. If the far modem cannot do V.8,
D-Modem tries V.32bis, V.22bis, V.21, V.23 and Bell 103, in that
sequence. `AT+A8E` (V.251) controls V.8 and V.8 bis.

For the menus that D-Modem sends, refer to
[the technical details](v8-details.md#v8-in-d-modem). For the start-up of
the D-Modem pumps, refer to [V.8 and V.34](../dsp/v34.md).
